# Immigration AI Lab

An AI Systems Engineering apprenticeship focused on immigration law, policy analysis and trustworthy legal AI.

## Purpose

This repository documents a structured programme of study aimed at developing sufficient AI Systems Engineering literacy to design, build, evaluate and defend an Immigration Policy Analyst System.

The objective is not to become a generic AI engineer.

The objective is to combine subject-matter expertise in immigration and nationality policy with a practical understanding of:

- Python
- Software Engineering
- Retrieval-Augmented Generation (RAG)
- Information Retrieval
- Vector Databases
- LangChain
- LangGraph
- Google Agent Development Kit (ADK)
- Evaluation
- Human-in-the-loop governance
- AI Systems Architecture

---

## Guiding Principles

Four principles govern this project:

### Understand Before Abstracting

Frameworks come after concepts.

### Test Before Trusting

Working software is not automatically reliable software.

### Simplify Before Extending

The simplest adequate solution is usually preferred.

### Resume Rather Than Restart

Interrupted progress is not failed progress.

---

## Project Goal

To build an Immigration Policy Analyst System capable of:

- answering questions about immigration rules;
- retrieving authoritative sources;
- generating citations;
- comparing policy versions;
- identifying amendments;
- highlighting uncertainty;
- supporting human review.

## Evaluation Philosophy

Evaluation begins on Day 1.

Difficult immigration and policy questions are captured before the system is capable of answering them.

The objective is to create a growing body of test cases covering:

- amendments;
- commencement provisions;
- transitional arrangements;
- historical versions of rules;
- guidance versus rules;
- policy edge cases.

These cases will be used to evaluate future versions of the system.

---

## Anti-Slop Policy

No code is accepted solely because it was generated by AI.

Before code becomes part of the project I should be able to explain:

- what it does;
- why it exists;
- how it can fail;
- whether it is the simplest adequate solution.

The goal is understanding, not code volume.

---

## Ultimate Success Criterion

Success is not:

> "I built an AI agent."

Success is:

> "I understand how the system works, where it can fail, how it should be evaluated, where human judgment remains necessary, and why the architecture was designed the way it was."
